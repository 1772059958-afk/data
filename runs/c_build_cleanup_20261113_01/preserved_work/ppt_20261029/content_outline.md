## 03 原流程与开题要求的差距

**比较表**：

| 环节 | 原流程问题 | 本轮修正 |
| --- | --- | --- |
| 路由 | 无行为信号默认升级 | 证据不足保守固定 |
| 配对起点 | 固定新候选串入交互提示 | 序列化快照独立恢复 |
| 预算 | 收尾与多工具请求可能越限 | 调用前预检并持续记账 |
| 统计 | 真实 C 与无条件 ESC 混用 | 按真实决策分别评分 |

**讲稿**：
前期已经打通生成和判分链路，但有四处会影响结论解释。第一，证据不足时的默认方向与开题相反。第二，交互分支可能额外获得固定延续的信息。第三，预算上限没有完整约束到每次实际动作。第四，成本比较混用了两种不同策略。本轮首先修复这些实验条件，而后再讨论路由效果。

## 04 同一前缀下的两种运行模式

**正文表**：

| | 正式运行 | 配对诊断 |
| --- | --- | --- |
| 执行对象 | 路由选中的一个延续 | 可继续前缀失败的两条延续 |
| 起点 | A/C/D/E 复用实际前缀 | 固定与交互各恢复独立快照 |
| 预算 | 计入完整前缀开销 | 两分支获得相同剩余额度 |
| 用途 | 方法解决率与策略成本 | 升级价值与误判分析 |

**可突出一句**：固定分支的新候选不能进入交互分支输入。

**讲稿**：
新入口区分正式运行和研究诊断。正式运行只执行该策略选择的分支，同一实例和重复下，各组复用同一份实际前缀。配对诊断则只针对前缀失败且仍可继续的任务，两条分支分别恢复状态和干净仓库。它们拿到相同的前缀信息与剩余预算。双分支的总采集开销单独记录，不能当作部署时的策略成本。

**来源**：`docs/实验协议_开题对齐.md`“五组与两种运行模式”；`src/swe_repair/experiment.py`；`tests/test_experiment.py`。

## 05 路由与候选选择的修正

**正文**：

- 固定延续：证据不足，或局部应用、语法问题尚可修正。
- 交互延续：明显定位分歧、重复候选或新的范围外源码证据。
- 统一停止：硬预算、不可恢复环境故障或已有公开通过候选。
- 提交筛选：可应用、语法有效、范围合法，保留此前有效候选。

**讲稿**：
路由现在恢复了开题的保守默认选择。局部格式问题可以先在固定流程内修正；需要补充定位或调用关系证据时，才有升级交互的依据。定位集合会先规范到实际仓库路径，测试文件路径本身不算新的源码依赖。候选选择也增加了前置排除条件。公开测试通过只代表候选具备提交条件，最终解决与否仍由独立评测判断。

**来源**：开题 §4.3、§4.5；`docs/实验协议_开题对齐.md`“D 组规则顺序”“信息边界与候选选择”；`src/swe_repair/router.py`、`state.py`、`patchutil.py`。

## 06 预算贯穿前缀与交互执行

**正文**：

- 统一约束累计 token、实际模型请求、工具执行和墙钟时间。
- 前缀、失败请求、重试与验证均计入对应预算。
- 收尾调用占用原有额度，多工具回复逐项受限。
- usage 缺失时保守预留并标记未知，费用不冒称实付。

**小字**：当前 development 参数仅为开发安全限额，尚未校准冻结。

**讲稿**：
预算控制的变化是从“配置里有上限”变成“每次动作前检查”。固定流程的容器命令也计入全局工具执行数。交互会话最后一次提交补丁的请求从原有调用额度中预留，不再超出上限追加。中断或缺少 usage 的请求仍可能消耗资源，所以按保守上界记账并保留未知标记。真实负载下应使用什么预算档，还需要后续在开发集确定。

**来源**：开题 §3.1；`docs/实验协议_开题对齐.md`“预算与计费”；`src/swe_repair/execution.py`、`llm.py`、`interact.py`；`tests/test_core_contracts.py`。

## 07 历史 C/D 成本比较的更正

**显著标识**：历史 v2.3 重算，7 个 dev 实例，单次运行。

**数据表**：

| 策略 | 解决数 | 升级次数 | 估算策略成本 |
| --- | ---: | ---: | ---: |
| 真实 C | 4/7 | 4 | 0.574337 元 |
| 真实 D | 4/7 | 4 | 0.574337 元 |

**结论文字**：该样本中 C、D 同决策、同成本，不能声称 D 更省钱。

**小字**：原 0.688450 元来自所有实例无条件采用 ESC 的另一种策略。旧数据仅用于口径诊断。

**讲稿**：
这一页是对旧汇报的更正，不是新实验的效果。真实 C 遵守共享早停，实际升级四次，与 D 完全相同。重算后，两者成本都为约 0.574 元。原来列为 C 的约 0.688 元，是所有七个实例无条件采用交互结果的假想策略。因此，旧样本不能支持 D 比 C 省钱。配对分析还应排除三个共享早停实例，只剩四个可继续失败案例，不能把分母混用。

**来源**：`runs/offline_validation/cf_dev7_v23_reanalysis.json`：`historical_diagnostic_only=true`、`policies` 的 C_actual/D_actual、`paired_eligible=4`；`docs/项目分析_20261029.md` §6。

## 10 下一阶段的实验顺序

**正文**：

1. 获得授权后，在少量 dev 实例验证真实模型与容器链路。
2. 校准完整路由、预算及前缀比例，冻结模型版本和配置。
3. 固定 test 总体或分层子集，开展至少三次正式重复。
4. 报告实例聚类 95% 区间，并补消融、敏感性和人工审查。

**可突出一句**：当前配置保持 draft，付费执行保持关闭。

**讲稿**：
下一阶段先做小规模真实集成，确认模型工具接口、补丁应用和公开测试能按预期运行，再在开发集确定阈值和预算。正式测试前固定样本清单、模型版本和配置，不利用测试结果回调参数。主对照至少重复三次，以实例为单位重采样，保留同一实例的全部重复。最后通过消融与人工语义审查分析路由误判和失败边界。当前仍不开展付费实验。
