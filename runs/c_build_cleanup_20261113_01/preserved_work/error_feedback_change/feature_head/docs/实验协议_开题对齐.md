# 开题对齐实验协议

日期：2026-10-29。协议版本：`proposal_aligned_v1`。状态：开发草案，尚未校准和正式冻结，未获付费实验授权。

研究依据为用户提供的开题报告第 3 至 6 节，正文摘录保存在 `docs/开题报告正文摘录.md`。本文将开题要求落实为可验证的执行约束；与原开题有冲突时，应修正实现和本文，不得沿用已退役 v2 协议中的相反规则。

## 研究问题

| 编号 | 问题 | 必须提供的证据 |
| --- | --- | --- |
| RQ1 | 同模型、同信息和同资源上限下，混合方法能否提高解决率 | A/B/C/D/E 的指定总体结果与配对不确定性 |
| RQ2 | 前缀失败证据能否识别值得交互的任务 | 同快照、同剩余预算的固定/交互配对分支与误判分析 |
| RQ3 | 质量相近时能否减少资源消耗 | 总体解决率与 token、调用、时间及费用的质量成本关系 |
| RQ4 | 哪些失败可恢复，路由在哪里误判 | 失败类型、信号消融、敏感性分析及人工语义抽查 |

允许负结果。不以 D 必须优于 C、D 必须与 C 不同，或神谕缺口闭合率必须为正作为验收标准。

## 五组与两种运行模式

| 组 | 起点 | 前缀结束后的策略 |
| --- | --- | --- |
| A | 共享固定前缀 | 遵守共享停止条件，否则固定延续 |
| B | 相同初始 bug 描述与干净仓库 | 从零开始受限交互，使用完整单策略预算 |
| C | 与 A/D/E 相同的实际前缀 | 遵守共享停止条件，所有仍可继续的前缀失败均升级 |
| D | 与 A/C/E 相同的实际前缀 | 按下述失败证据规则选择固定、交互或停止 |
| E | 与 A/C/D 相同的实际前缀 | 遵守共享停止条件，按 dev 上冻结的触发率随机选择分支 |

正式模式每个实例/重复/组只执行选中的延续分支。A/C/D/E 复用同一实际前缀快照与上下文，不得因组别不同重新采样前缀。缓存标识应覆盖生效配置哈希、实例、种子和重复编号，并检查基线提交与镜像身份；每个策略都完整计入所继承的前缀开销，不能把缓存命中当作该策略零成本。

诊断模式用于 RQ2。仅对预先指定、前缀失败且仍可继续的实例运行两条分支。固定和交互分别从序列化前缀快照恢复独立状态与干净仓库，初始候选、文件正文、失败反馈和剩余预算一致。固定分支的新候选及验证结果不得进入交互提示。已有公开通过候选或硬停止的实例不进入“可继续失败”的配对分母。

双分支生成开销是研究诊断成本，不能混入可部署策略的成绩。ESC 是交互分支的诊断标签，不是第六个对照组；“所有实例无条件采用 ESC”也不等于真实 C。

## 信息边界与候选选择

生成侧只接收 `instance_id`、`repo`、`base_commit`、`version`、`environment_setup_commit`、`problem_statement` 及干净 checkout 可发现的内容。开发者补丁、官方测试补丁、FAIL_TO_PASS/PASS_TO_PASS、最终判分与 hints_text 不进入生成、路由或候选选择；隐藏测试文件名也不能用于定位。

多次定位先解析为同一仓库的规范路径，再计算集合 Jaccard 分歧。路径表示差异和双方均缺失不能冒充定位分歧。文件读取顺序稳定；记录实际读到的文件、字数截断、符号、候选差异、应用状态、语法状态、公开测试命令/输出和错误指纹。

每个候选是针对干净基线的完整 diff。每次候选验证后回滚，保留此前有效候选；不能通过多次增量编辑污染比较起点。先排除无法应用、语法无效及越界候选，再按公开验证、修改规模、生成顺序选择。首版修改范围限 Python 源码，禁止修改测试和仓库元数据；若需扩展范围，须在 dev 阶段修改协议与配置并重新验证。

公开测试缺失、导入失败、收集失败、超时和断言失败分别记录。公开通过仅表示可提交，最终解决与否只由补丁冻结后的独立评测决定。

## D 组规则顺序

1. 环境故障经过预先指定的一次确定性恢复仍不可运行，停止。
2. 任一资源硬上限已到，或不足以完成最小延续，停止。
3. 已有有效候选通过公开验证，冻结候选并停止。
4. 最新失败是可局部修正的补丁应用或语法/导入问题，且无新的范围外源文件证据，固定延续。
5. 定位分歧超过 dev 冻结阈值，升级交互。
6. 规范化补丁重复率超过 dev 冻结阈值，升级交互。
7. 失败堆栈揭示尚未检查的仓库源码调用关系，升级交互。测试文件和测试运行器本身不构成此证据。
8. 证据不足但环境可运行，保守固定延续。
9. 其余情况固定延续。

该顺序对应活动配置的九条规则。停止条件对所有可比组一致。开发校准必须回放完整状态与完整规则，不能仅用两个数值信号的 OR 近似 D；不得为了制造 D/C 分歧事后改变规则。

## 预算与计费

每个策略有统一的累计输入输出 token、实际模型请求次数、工具调用和墙钟上限。前缀、失败请求、重试、验证、反馈和收尾都计入。模型重试不是免费请求，交互收尾从会话模型调用额度内部预留；不允许在上限之外额外追加一次。

活动配置以 `container_exec` 作为全局工具计数单位，固定流程的索引、读取、应用、编译和测试命令也计数。六种具名交互工具另有会话内调用上限，一个回复的多个请求不能越限；生命周期准备/清理另行记录。模型请求与工具执行均受剩余截止时间限制。请求中断而缺少 usage 时保守预留资源/金额并标记未知，不能称为实付或精确用量。

前缀 token 配额受其占比限制，延续继承已消费预算。诊断的两个备选分支各复制同一剩余额度；不能让第一条分支消耗第二条分支的策略预算。批次总金额上限、单实例上限与四元资源预算分别强制执行。

`configs/proposal_v1.json` 中的 development 档、0.30 前缀占比、输出上限和交互次数仅是开发安全限额，不是已校准的主实验参数。模型版本与路由阈值仍为 pending/null。不得自行改成“已冻结”以绕过预检。费用表计算值是估算，账单另行核对；缓存费用必须与统一的策略计费口径一起解释。

## 数据与统计

主总体为 SWE-bench Lite test 300 个实例，dev 23 个只用于调试与校准。资源不足时，在观察正式方法结果前固定分层子集、抽样种子、清单哈希和结论范围。已有 98 个 gold 通过实例是镜像可用性形成的历史便利覆盖，不直接决定新主总体。

金标准失败只说明参考补丁在当时环境下未通过，不证明所有补丁绝对不可解。主分析保留预先指定总体及其中的环境失败，另报所有组均可运行的共同子集；未提交、未评测、基础设施错误、真正未解决与解决分别标记。不能把不在 resolved_ids 中的实例全部记为未解决。

各组在相同实例上至少重复三次，记录种子和 repeat index。报告解决率绝对差与实例为单位的 cluster bootstrap 95% 区间，同一实例的全部重复必须一起抽样；同时报告逐仓库结果和仓库宏平均。每解决一题成本使用全部指定任务总开销除以解决数，零解决时为未定义。

四象限、特征 AUC 与神谕只在 eligible 且两分支均有有效判分的实例上计算，并显式报告缺失与环境问题。神谕只能表示理想上界，不计入 A–E 方法成绩。相同决策和相同分支结果的 C/D 应得到相同策略成本；闭合率允许为负，分母没有增益空间时未定义。

随机组 E 的概率来自 dev 上完整 D 策略在 eligible 实例中的交互触发率，而非交互分支的胜率。正式阶段冻结该概率，报告实际触发次数；不得利用 test 标签回调。

正式验证还须分别去除定位分歧、重复信号、结构化反馈和停滞控制，考察前缀占比、阈值和交互步数的敏感性，并分层人工审查补丁语义。只有主对照完成不能声称 RQ4 已回答。

## 当前授权与结果管理

当前用户明确要求只完成离线验证，不运行付费实验。本次及后续 agent 都不得依据旧 README、旧配置、旧命令或本文件推定已获付费授权。未来需由用户明确解除该限制后，才可设置运行授权并使用显式执行开关。

默认入口只生成离线计划。新实验输出到新的 `runs/<tag>/`，保存生效配置、哈希、实例清单、镜像/提交身份、调用记录、完整前缀快照和阶段事件；禁止覆盖已有 tag。阶段检查点有助于审计，不代表已经实现安全续跑。中断后先核对已发送请求与费用，再决定新运行。

原有 `data/`、`reports/` 的 93 个文件保持字节不变；旧配置、协议、基线入口和交付物已移到 `dustbin/`。旧结果仅作历史诊断，不能混入本协议主结果。

2026-10-30 错误反馈细化：失败快照保存实际捕获的完整 stdout/stderr 文本；指纹继续使用原有规范化规则，模型反馈另选异常、断言、真实源码行号及输出尾部，不再只截取日志开头。前缀交接与固定延续使用同一有界 prompt view，交互补丁验证和追加公开检查使用同一摘要器。六种工具保持不变，`read_region` 的 `log:<sha256>` 路径只解析当前分支状态内已捕获的公开生成日志；start/end 为原始日志行号，offset 支持超长单行续读。每页最多 3000 字符及 120 行，计入具名工具次数、后续模型输入 token 和墙钟预算，不访问容器或宿主任意日志文件。追加检查的日志单独审计，不借此改变原路由和候选判定。旧快照没有原始输出时明确标注不可用，不补造日志。提示版本变更并保持 pending/未授权，仍需 dev 校准与真实集成验证。
