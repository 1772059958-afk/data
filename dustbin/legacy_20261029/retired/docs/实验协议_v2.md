# 实验协议 v2（冻结草案）

> 起草：2026-10-23　　状态：**草案，待组内确认后冻结哈希**
> 适用范围：本学期全部对照实验。任何与本文件冲突的实现，以本文件为准。

## 1. 主张（一句可证伪的话）

> 在共享前缀结束的那个固定决策点上，**只用前缀自身算得出的失败证据**（可行候选数、
> 定位分歧度 u_loc、补丁重复率 u_dup、是否存在行为信号）就能预测"升级到受限交互是否值得"。
> 一个只用这些特征的规则，在同等预算下能闭合"每次都升级"所获收益的大部分，而成本显著更低。

**空假设（要被否定的那个）**：上述特征对"升级的边际价值"没有信息量。
若成立，路由的收益应约等于随机路由（E 组），且神谕缺口闭合率接近 0。

**本工作不是**：新的修复系统、新的模型、或与 Agentless/SWE-agent 比总解决率。

## 2. 六条边界

| # | 边界 | 冻结内容 | 为什么必须钉死 |
|---|---|---|---|
| B1 | **决策边界** | 每个实例上路由器**只决策一次**，位置固定在前缀结束处（前缀占预算 30%）。不做连续、多步、树状决策 | 单决策点才能做干净的反事实：只有两条分支，不是一棵树。这是自设限制，换来可测量性 |
| B2 | **信息边界** | 路由器只能看：`可行候选数`、`u_loc`、`u_dup`、`behavioural_signal`、`剩余预算`、`环境是否失败`。**禁止**任何形式的 `FAIL_TO_PASS` / `PASS_TO_PASS` / `test_patch` / `patch` 内容进入生成或路由视图，**包括测试文件名** | 旧基线曾用 `FAIL_TO_PASS` 的测试**文件名**去抓文件，属于越界，本协议下禁止。`state.assert_generation_only` 强制执行 |
| B3 | **预算边界** | 五组统一 `small` 档：`token=32000, model_call=12, tool_call=20, wallclock=600s`。主实验**不扫预算档位网格** | 主张是"等预算比较"，预算就必须是常量。原来的 3 档 × 3 阈值 × 3 重复是组合爆炸，每个格子都没有理论依据 |
| B4 | **方法边界** | 前缀、候选生成、校验这三块在 A/C/D/E 四组中**完全共用同一实现**，唯一变量是"前缀之后怎么走"。B 组不跑前缀，从零开始交互，用同一执行器 | 否则无法归因。这也是防止被问"为什么你们解决率不如 Agentless"的唯一防线 |
| B5 | **评估边界** | 评估池 = 已通过金标准验证的 **98 个 test 实例**（django 92 + astropy 6）。明确声明这是**受算力限制的便利子集，高度偏向 django**；不宣称对另外 10 个仓库有效；astropy 6 个仅作案例不作统计 | 把"没下载全"从隐含缺口变成公开边界。这条直接回应"边界没限定好" |
| B6 | **主张边界** | **可**建立：该池、该预算、该模型下，前缀特征是否有预测力、路由能否闭合神谕缺口。**不可**建立：跨模型泛化、更大预算下的行为、未入池仓库的结论 | 提前画射程，比事后解释安全 |

**补充口径**：dev 的 15 个金标准可解实例只用于符号检查、消融与阈值校准，**不进主结果表**。
dev 分布在 4 个仓库，评估池是另外 2 个仓库，因此"跨仓库转移"本身是一条要报告的发现。

## 3. 五组定义

| 组 | 跑共享前缀 | 前缀之后 | 决策依据 |
|---|---|---|---|
| **A** 固定流程 | 是 | 固定延续：继续生成候选，不调工具 | 无（看共享停止规则） |
| **B** 纯交互 | **否** | 从零开始受限交互（6 工具 / 4 状态 / 停滞 3 次） | 无 |
| **C** 简单级联 | 是 | 前缀无可行候选 → 升级 | 无（所有可继续的失败都升级） |
| **D** 自适应混合 | 是 | 按前缀证据决定 | 8 条冻结规则（见 §5） |
| **E** 随机路由 | 是 | 按概率 p 升级 | 抛硬币 |

A/C/D/E 的差异**只在"前缀之后"**。B 是异类，用来回答"不要前缀、直接全程交互值不值"。

## 4. 反事实矩阵与四象限

每个实例跑一次前缀，然后**两条分支都跑**（A 的延续、交互升级）。路由只"采用"其中一条，
但两条都记录。这样一次投入拿到全部反事实，之后任何路由策略（含随机、神谕、消融）都能离线评估。

| | 交互成功 | 交互失败 |
|---|---|---|
| **固定成功** | ① 双重成功 → 升级是**纯浪费** | ② 只固定成功 → 升级**有害** |
| **固定失败** | ③ **只交互成功 → 升级必要（靶心）** | ④ 双失败 → 升级**无望** |

要报的三个数：

1. **③ 在池中占比** —— 决定"精准识别"的动机有多强。
2. **特征能否挑出 ③** —— 每个特征对标签 `Δ = ①{固定失败 ∧ 交互成功}` 的 AUC。
3. **神谕缺口闭合率** = (R_D − R_A) / (R_oracle − R_A)，落在 [0,1]。

成本侧：等解决率下的成本、等成本下的解决率，以及 ①② 的占比（证明无脑升级在烧钱）。

**本次允许的临时偏离（必须在结果表上标注"占位"）**：

- 路由阈值用 `0.50` 占位（未校准，仅用于让机器跑起来）
- E 组升级概率用 `0.50` 占位
- `repeats = 1`（方差与重复实验留到主实验）
- 交互会话上限收紧为 **6 次模型调用 / 8 次工具调用**（配置 `small` 档为 12/20）。五组统一收紧，故"等预算"不变；目的只是把总花费压在 10 元以内。
- 升级分支另以 `ESC` 名义**单独判分**。它不是一个对照组，只用于填满反事实矩阵的格子——否则在所有组都提前冻结的实例上，"交互是否也能解"这一格会永远空着。
- **预算档修正（v2.1，有实测依据）**：B3 冻结的 `small` 档为 `token=32000`，但首次 smoke 实测**一个前缀就用掉了 47009 token**（3 次调用 × 约 15k 上下文），于是 `stop_when_budget_insufficient` 在每个实例上都触发，A/C/D/E 四组的决策**全部为 stop**，实验什么都没测到。现改用 demo 档 `token=200000, model_call=12, tool_call=20, wallclock=600`。这是对 B3 的修正，不是为凑结果调参：原值从未与实际上下文规模核对过。

**修正前的失败留档**：`reports/cf_smoke1_matrix.json` 保留了 budget 缺陷下的原始结果（四组决策全为 `stop`、五个补丁全空），作为"档位不当会让五组同时失效"的证据，不再重跑覆盖。

### 6.1 v2.2：信号链修正（2026-10-23）

**问题**：`state.behavioural_signal()` 的三值语义里，`behavioural` 需要"检查产生了行为结果（断言通过**或断言失败**）"。
但前缀实现只 import 了 `FailureLog`/`FailureRecord`，**从未写入一条记录**，于是：

- 规则 1 已先拦掉"公开测试通过"的实例；
- `repro_reproduces` 从不为真；
- `failures.classes()` 恒为空；
- 结论：`behavioural_signal()` 在所有能走到规则 4 的实例上只能是 `non_behavioural` 或 `none`，
  规则 7 必然触发，**D 永远升级，D ≡ C**。这与预算、阈值、样本量无关。

**修正**：公开测试失败时构造 `FailureRecord.from_output(stage="test")` 并写入 `state.failures`，
让 `fingerprint.classify` 决定它是不是 `behaviour_assertion`。回归测试见 `tests/test_signal_chain.py`。

**这不是为了让某个组好看而改判定**：分类器、三值语义、阈值网格都已存在，缺的只是把检查结果接进状态机。
但必须按改规则留痕——**v2.1 与 v2.2 的结果不可混用，不可拼在同一张表里**。

**已知限制（本轮不修，先测量）**：`out_of_scope_frames()` 取的是**最近一条**失败记录的栈帧，
而 pytest 的 traceback 几乎必然包含测试文件路径，该文件通常不在已读上下文内。
因此规则 6（`interactive_on_out_of_scope_stack_evidence`）会抢先触发升级，D 仍可能等于 C。
本轮改为**如实记录每条规则是否触发**（`router.evaluate_all` 全表写入矩阵），
待测出其占比后，再与导师确认规则 6 是否需要收窄（例如只统计非测试文件）。

### 6.2 v2.3：执行器收尾与公开测试发现（2026-10-23）

v2.2 之后 D 仍等于 C，但原因从规则 7 转移到规则 4；更严重的是 **7 个实例里 6 个交互会话交空补丁**，
使"全升级"从 A 的 3/7 掉到 1/7。两处修正：

**（a）强制收尾**：交互会话若在预算耗尽时仍无补丁，**额外保留 1 次无工具调用**，要求它把当前最好的补丁交出来。
该调用计入模型调用数与花费，但不占工具调用额度。语义上它把"会话探索过但没写东西"与
"什么都没学到"区分开——否则执行器缺陷会被误读成路由缺陷。

**（b）公开测试发现**：原先只找与模块同名的 `test_<stem>.py`，导致 astroid/sqlfluff **全部** `not_applicable`、
`checks_run=0`、`behavioural_signal` 恒为 `none`。现改为两路并行：
名称匹配（`test_<stem>.py` / `<stem>_test.py`）+ **内容匹配**（在 `tests/`、`test/` 下的测试文件中
搜索模块名或定位阶段给出的符号）。仍然只读 checkout，不碰评测元数据。

**（c）提示词**：`@@` hunk 必须各自带 `--- a/<path>` 与 `+++ b/<path>` 头。
`astroid-1196` 的两个候选就是因为缺文件头被 `extract_patch` 判空。

**版本隔离**：v2.1（无失败记录）、v2.2（有失败记录）、v2.3（+收尾+测试发现）的结果**互不可比**，
不得拼在同一张表里。

**预先登记的检查（跑之前定好，跑完不许改）**：

若 D 组的逐实例决策与 C 组完全相同，则判为**规则集结构缺陷**并如实报告，**不得**事后调整规则或阈值去制造差异。该检查由 `scripts/analyse_cf.py` 的 `arm_equivalence` 字段自动输出。

**本次不报**：任何解决率排序、任何显著性检验、任何"某组更强"的表述。
