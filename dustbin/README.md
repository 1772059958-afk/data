# 退役实现与历史材料

这里保存 2026-10-29 按开题报告恢复研究方向前的实现和文档。`dustbin` 是可追溯归档，不是可执行实验入口。

`legacy_20261029/` 以代码提交 `3759265` 为基准，保留修复前的 `src/`、`scripts/`、`tests/`、`configs/`、`docs/` 和原 README。`retired/` 保存从活动目录移出的旧入口、配置、协议与周报交付物。相同内容可能同时出现在快照和 `retired/` 中，这是为保留原目录结构与退役去向。

原始实验数据仍在项目根目录的 `data/` 和 `reports/`，没有因为退出正式主结果而删除或改写。其 93 个原始文件由 `legacy_20261029/preservation_manifest.json` 逐一记录 SHA-256。旧实现与退役文件的哈希另见 `archive_inventory.json`。

```powershell
python scripts/verify_preservation.py --archive
```

退出活动流程的原因主要包括：

- 旧协议将“无行为信号”默认送入交互，与开题的保守固定延续相反。
- 旧基线使用隐藏测试路径等额外信息，不能成为新协议的公平对照。
- 旧双分支驱动存在状态串扰，预算没有贯穿执行。
- 周报将真实 C 组与无条件采用 ESC 的策略混用，成本比较需要更正。
- 旧配置仍待校准，名称 `frozen_v1` 不能作为已冻结的证据。
- 旧 gold 扫描包装、冻结清单和汇总入口会写原 data/reports，或将失败默认排除；新入口使用独立的 runs 输出和明确总体。

这些材料可用于故障回归、审计和研究过程说明，不能与新协议的数据合并计算效果。不要从这里导入模块、启动 Shell/PowerShell 入口、复制旧路由规则覆盖活动配置，或重新生成旧结果文件。
