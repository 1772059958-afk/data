1. 指定 dev 总体为 `data/frozen/instances_dev.txt` 的全部 23 例。每例保留环境、生成、评测状态；环境失败、缺失快照、缺失判分分别列出，不替换实例。
2. 负载检查使用仅依实例 ID 与仓库分布选出的 3 例，选择种子为 20261111，先保存清单及 SHA256，再运行。不能按旧解决率、gold 标签、镜像是否已下载或新结果换例。该 3 例不等于完整校准总体。
3. 所有新运行写新的 `runs/<tag>/`，保留配置/源码/清单哈希、模型服务身份、镜像 digest 与 base commit、实际 usage、阶段事件和完整快照。旧运行和历史记录不覆盖。
4. `.env` 只在获授权的真实请求阶段由项目凭据入口读取。公开环境准备不得挂载凭据；本方案离线组织阶段不读取 `.env`。
5. dev 的模型、输出上限、采样、提示、前缀候选数、预算、交互设置或公开环境身份发生变化后，不混用旧配置的前缀、配对标签或缓存。每种配置使用独立 tag 和身份；阈值离线回放则必须绑定产生该状态的完整执行配置。

## 4. 有限资源选择，避免笛卡尔网格

以下是**候选检查顺序**，不是已选定的正式参数，也不是自动升级额度的权限。具体金额上限、候选数值与执行配置在 D2 开始前保存为新的审阅文件。当前 development 数值仅作为第一个负载参照：512000 token、12 次全局请求、80 次 container exec、1200 秒；prefix 2 候选、占比 0.30；固定最多 6 候选；交互 6 次会话请求、10 次具名工具、420 秒，收尾包含在额度内。

1. **先检查一种基准资源配置。** 在同一 3 例上运行 prefix、eligible 的固定/交互配对，并检查独立 B。记录输出截断、预算拒绝、候选可应用/语法状态、验证是否启动、会话最后有效动作及各资源实际消费。没有解决但没有资源截断的轨迹不得自动判为“应该加预算”。
2. **最多追加一种资源配置。** 仅在基准中出现可复核的输出截断或会话/全局额度不足，才评审一个针对该约束的预先落盘候选；保持其余设置不变，或逐项列出无法分离的变更。新候选仍在相同 3 例完整检查，不能只重跑失败组。追加金额先获授权。无触发条件则保留基准，不为追求成功继续搜索。
3. **资源配置确定后单独选择 prefix 占比。** 在同一 3 例比较预先列出的 0.20/0.30/0.40；已经完成且身份相同的 0.30 记录可引用，不重复付费。每档都从该档实际 prefix 的同一快照给两分支相同剩余预算。资源档与 prefix 比例不作全笛卡尔组合。
4. **prefix 选择标准先于结果固定。** 先排除不能完成预定 prefix 工作，或对仍需延续的实例无法保留最小延续额度的档位；对剩余档位先比较完成有效流程的覆盖（已有公开通过候选而共享停止，或取得有效配对，两者均计入流程完成），再比较可应用且语法有效候选覆盖，平局选择较小 prefix 占比。不以增加 eligible 失败数作为优化目标。公开通过造成共享停止单列；不把它伪装为“缺失配对”。若没有可用档位，停止并记录设计未通过资源检查。
5. **前缀/固定候选数与交互设置一并审阅。** 不在正式 test 中改变候选数、停滞、固定延续次数、最小延续预算或会话上限。若 D2 显示现有候选数使目标信号不可辨识，应在 D3 前选择保留该限制或重新设计，并写明原因；不能只把不可达阈值称为已校准。
6. **固定后才进入全 dev。** D3 只跑选定的一种执行配置。完整 dev 若发现系统性环境/执行缺陷，则停止、修复、重新离线验证并使用新配置/tag；不从旧配置挑选成功案例合并。是否新增一轮须重新核对剩余金额和请求账本，不自动重试。

上述小样本顺序选择服务于资源可用性，不能据此声称资源最优或完成了前缀/步数敏感性。完整多预算质量成本曲线及系统敏感性另立研究预算；此次 test 20 单次只能提供一个冻结预算档位下的比较点。

## 5. 信号、校准目标和 E 的分母

**定位分歧的操作定义。** 当前实现是问题文本路径的词法提取与一次模型定位，经仓库规范路径解析后计算 `1 - Jaccard`，应称为异质定位器分歧。不能将其表述为同一模型多次采样的不确定性。保存两边为空、单边为空、两边非空的数量和路径证据；缺失不冒充高分歧。若改为多次模型定位，增加的请求必须计入 prefix，并重新产生对应快照和标签。

**重复信号可达性。** 当前定义为重复候选数/全部候选数，n 个候选的最大值为 `(n-1)/n`，触发使用严格 `>`。因此 n=2 时阈值 0.50、0.75 不会触发；它们只能作为显式关闭重复规则的对照。D3 前须选择并记录：保留两候选并承认网格中的关闭区间，或变更候选数/网格后重新检查资源。现有脚本共用定位/重复率网格；需要分别定义网格时先实现及离线验证，不能在报告里假称已有独立网格入口。

**完整策略回放。** 保留九条规则顺序：环境与预算硬停止、公开通过冻结、局部应用/语法错误优先固定、定位分歧/重复/新增范围外源码触发交互、证据不足保守固定。测试文件不构成范围外源码证据。拟合不能简化成两个数值信号的 OR。

**预先确定选择目标。** 沿用现有可审计排序：先最少路由 regret，再最多被选分支解决数，再较低交互比例，最后较高阈值平局规则。该目标只在有效配对中计算，保存全部网格分数；不为 D 必须优于 C 而换目标。披露训练内拟合性质，不把同一批 dev 标签同时当成独立泛化验证。

**两种分母分别保存。** `observations` 只包含 eligible 且双分支有效判分的配对，用于阈值拟合和四象限；`eligible_prefixes` 必须覆盖全部可继续失败，用于选定完整 D 的交互触发率。E 概率为后者的 `interactive/eligible`，不是交互胜率，也不是 complete-pair 子集的比例。保存缺失判分清单、触发来源及概率哈希。

零 eligible 时无法从本轮 dev 估计 E 概率；不能自动填 0、1 或沿用两例 pilot 的 1.0。只有平局、有效配对极少或没有两种分支互补时，候选报告必须明确证据不足；网格平局和 `stable=true` 不能证明路由有效。此时先报告退化与限制，再审阅是否采用预注册启发式协议及其结论边界，不能将其改名为成功校准。

## 6. 模型身份与冻结门槛

- `deepseek-flash` 服务响应别名只证明某次接口身份，不等于不可变模型版本。正式前需记录实际服务版本、是否可固定、请求采样参数的服务端行为及身份探测证据；无法固定时明确阻塞项或另行审阅可复现性受限的协议，不能把别名伪装成版本冻结。
- temperature、top_p 等为空时先核对接口是否支持及实际默认值；支持则明确保存，不支持则记录固定的服务行为与限制。真实探测须在新授权范围内。
- 冻结对象包括模型、采样、提示、预算档、prefix 比例/候选、固定延续、交互步数/工具/停滞、完整路由、E 概率、候选选择、公开环境和统计口径。不能只冻结两个阈值。
- 正式前保存一个审阅过的完整配置与哈希；执行授权单独核验。阶段检查点不意味着可自动安全续跑；账本出现 pending 时先核对已发送请求和 usage。

## 7. 与 20 例五组单次 test 的交接

dev 专用草案配置为 `configs/dev_calibration_20261111.json`。正式预注册清单为 `runs/test20_preparation_20261111/instances.json`，从完整 test 300 按仓库分层抽取 20 例，抽样种子和运行种子均为 20261111，repeat_index=0，组为 A/B/C/D/E。正式专用配置为 `configs/test20_single_20261111.json`，保持 pending 到真实校准和审阅完成；不能从历史 98 个 gold 通过案例抽取，也不因环境失败、无补丁或不佳成绩补例。

正式 A/C/D/E 共用同一实际 prefix，各自完整计入 prefix 策略成本；B 从相同初始信息开始。正式只执行选中的延续，诊断的备选分支不进入 test 成绩；另报真实新增生成与诊断开销。test 标签不回流校准，五组冻结后独立判分，100 个策略单元的缺失、环境失败和未解决分别保留。

用户本轮缩小到单次运行，结果采用描述性解决数/20、逐实例配对差异、资源总量及每解决成本；零解决时每解决成本未定义，缺失 usage 标记未知。报告逐仓库及共同可运行子集时显示分母；不输出三重复置信区间、显著性或质量等价结论，不声称覆盖原开题完整统计验证、完整 RQ2/RQ4 或多预算曲线。

单次协议的入口与离线验证状态以本轮根目录准备说明为准：默认正式入口和多重复汇总原有的三重复门槛不能全局删除，应以本轮专用协议、清单和单次描述性口径绑定例外；不能用 dev pilot 模式代替 test 正式运行。

## 8. 预算审阅和产物清单

真实预算待用户确认。当前 dev/正式草案沿用主配置的 6 元批次/2 元实例仅为安全占位，`budget_status=pending_new_authorization`；这不足以表明已批准或足以跑完整阶段。确认实际批次上限后另存最终生效配置，不回写一个虚假授权。至少分开列出：公开环境准备/镜像/磁盘与时间，少量 dev 负载检查，完整 dev prefix 与配对生成，独立容器判分，test20 五组单次，后续人工审查。每阶段设金额与四元资源硬守卫，跨进程共享批次账本，未知 usage 保守预留；不能把旧 100 元“余额”转入新授权。
