## 真实集成前的验收顺序

1. 取得真实容器及付费生成的明确授权，确认阶段范围与金额上限；当前不执行。
2. 在实际 WSL/Linux 环境确认依赖版本、本地镜像、实际 container image ID 和 base commit，记录结果；不得把镜像/安装故障读作方法失败。
3. 固定并验证服务端模型版本，先验收首例的实际请求计数、工具消息、完整补丁应用和公开测试命令。预算不足应分类记录，不能靠上限之外追加收尾。
4. 首例行为符合预期后才推进其余两例。若有失败，保留该实例、失败阶段、原始日志、保守预留费用和已验证候选。
5. 补丁冻结后独立判分并生成 sidecar，再分析；小范围结果只用于接口/环境验收。
6. 后续仍须完整 dev 校准预算、前缀比例、固定/交互步数和完整 D 策略，按全部 eligible 前缀匹配 E，经审阅再冻结；不能直接开始正式 test。
